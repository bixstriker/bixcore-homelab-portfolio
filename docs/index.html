BiXCore

BiXCore is the network I built at home, both for the services I use every day and for experimenting with technologies I want to understand better. It has grown into an OPNsense gateway, managed switching and Wi-Fi, Windows Server and PKI, NAS services, and a separate Proxmox firewall lab.

I document what I set up, the problems I ran into and how I worked through them.

HOW IT WORKS

A working network and a separate place to experiment

The OPNsense gateway, switches, Wi-Fi, directory services and NAS are part of my day-to-day setup. Proxmox is different: I start it when I want to compare firewall systems or test a configuration with Windows and Linux clients.

The lab uses dedicated virtual networks and a separate upstream. I have checked the main connectivity paths and am continuing the tests for traffic that should be blocked.

WHAT'S NEXT

What I’d like to try next

There are several directions I want to take BiXCore: finishing recovery and IPv6 tests, learning other firewall platforms, and trying new security and networking features with real clients.

More firewall platforms

Broader FortiGate tests and evaluation of Palo Alto VM-Series, Juniper vSRX, Check Point, SonicWall and Cisco virtual routing.

RADIUS, NAC and real Wi-Fi clients

A dedicated access point for captive portals, EAP-TLS and PacketFence, plus BGP/FRR experiments in the virtual lab.

IPv6 and recovery

An IPv6-only lab network, real provider prefix-change tests, stronger isolation checks and proper restores of important services.

Zenarmor and encrypted traffic

More work with web and application policies, TLS inspection, reporting and performance on the N305 gateway — including multi-core tests if the feature becomes available.
