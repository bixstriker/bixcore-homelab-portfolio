The Virtual Firewall Lab

My Proxmox lab lets me work with firewall systems without replacing the OPNsense gateway I use every day. I can build a configuration, connect a Windows or Linux client, test the traffic and then move on to another platform.

How the lab works

Proxmox runs on a reused desktop with Debian 13. I have a dedicated upstream for the test firewalls and separate Linux bridges for their LAN interfaces. The same client VMs can be attached to the firewall being tested, so I don't need a large number of machines running at the same time.

As of 4 November 2026 the lab contains 13 virtual machines: 11 router/firewall platforms and two reusable Windows/Linux test clients. In addition to MikroTik CHR, pfSense CE, Sophos Firewall Home, VyOS, FortiGate VM, OpenWrt and IPFire, I installed NethSecurity 8.8, FreeSense 1.1.11, DD-WRT r66445 and a separate OPNsense Community 26.7 guest. Each firewall has its own virtual LAN, connected only when needed to the shared test clients. I verified basic management, IPv4 connectivity, DHCP, NAT and selected RDP forwards with the four new systems. Full negative-path and performance tests are not yet complete.

Problems I encountered

The VLAN path for the lab WAN caused a DHCP investigation that went all the way from the gateway to the physical switch and the virtual NIC. I also corrected an upstream bridge mistake during the IPFire setup. Those are described in the troubleshooting notes. More recently, DD-WRT required an unusual UEFI boot repair: the wrong root partition and filesystem were embedded not only in GRUB configuration but also in a binary configuration template. Correcting the template and the UEFI reboot parameter gave two successful restarts. The boot case and an SSH blocklist incident are documented separately; DD-WRT shutdown is still not solved.
