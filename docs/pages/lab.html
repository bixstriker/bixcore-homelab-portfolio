PROXMOX / FIREWALLS / CLIENT TESTS

My Virtual Firewall Lab

I use Proxmox to try different routers and firewalls without changing the gateway that runs my everyday network. Windows and Linux clients make it possible to check the results from the other end of a connection.

How I built it

The host runs Debian 13 and Proxmox VE 9.2. Each active firewall has a lab-side uplink and its own virtual LAN, with test clients attached as needed. There are now 13 documented virtual machines (11 firewall/router systems and two client VMs), but I normally run only the ones required for a particular experiment.

Firewalls in the lab

I have worked with MikroTik CHR, pfSense CE, Sophos Firewall Home, VyOS, FortiGate VM, OpenWrt, IPFire, NethSecurity, FreeSense, DD-WRT and a separate OPNsense Community guest. The first tests covered installation, management access, DHCP, DNS, NAT and selected port forwards. Coverage differs between the platforms; they have not all completed the same feature checklist.

Other Proxmox projects include directory integration, trusted HTTPS, storage recovery and Intel iGPU passthrough for a Linux desktop. My latest DD-WRT experiment involved diagnosing a UEFI kernel panic and fixing a persistent GRUB template; reboot now works, but shutdown still needs investigation.

What still needs work

  • A consistent throughput and latency comparison.
  • Negative-path tests between all relevant zones and the home network.
  • A full recovery test for the current single-disk VM storage.
  • Experiments with physical Wi-Fi clients and an IPv6-only lab uplink.
