PROXMOX / FIREWALLS / CLIENT TESTS

My Virtual Firewall Lab

I use Proxmox to try different routers and firewalls without changing the gateway that runs my everyday network. Windows and Linux clients make it possible to check the results from the other end of a connection.

How I built it

The host runs Debian 13 and Proxmox VE 9.2. Each active firewall has a lab-side uplink and its own virtual LAN, with test clients attached as needed. The latest verified inventory contains 18 virtual machines: thirteen firewall/router instances across twelve platforms, two Windows/Linux clients, and PacketFence, OpenWISP and Taranac. I normally run only two or three VMs when testing.

Firewalls in the lab

I have worked with MikroTik CHR, pfSense CE, Sophos Firewall Home, VyOS, FortiGate VM, OpenWrt, IPFire, NethSecurity, FreeSense, DD-WRT, OPNsense and OpenFW. I keep two independent OPNsense guests for different lab tasks. Basic installation, management, DHCP, DNS, NAT and selected forwarding tests differ by platform; the original physical-laptop test set covered eleven firewall instances, not every VM added later. I have not completed the same security and recovery checklist for all twelve platforms.

Other Proxmox projects include directory integration, trusted HTTPS, storage recovery and Intel iGPU passthrough for a Linux desktop. My latest DD-WRT experiment involved diagnosing a UEFI kernel panic and fixing a persistent GRUB template; reboot now works, but shutdown still needs investigation.

What still needs work

  • A consistent throughput and latency comparison.
  • Negative-path tests between all relevant zones and the home network.
  • A full recovery test for the current single-disk VM storage.
  • DHCPv6 prefix delegation to a virtual router over the existing IPv6-only lab uplink, plus a dedicated isolated Wi-Fi test access point. The IPv6-only network itself has already been tested with real Windows and Android clients.
