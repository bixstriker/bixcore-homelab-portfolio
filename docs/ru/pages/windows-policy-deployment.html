Управление Windows через групповые политики

После включения дополнительных компьютеров в Active Directory я хотел автоматически применять общие настройки и инструменты администрирования. Групповые политики делают это воспроизводимым вместо настройки каждого ПК с нуля.

Перенос существующих ПК в домен

Не хотел терять накопленные за годы локальные профили при включении Windows в AD. Использовал ForensiT User Profile Wizard для привязки существующих профилей к доменным учётным записям, затем проверил принадлежность рабочего стола, приложений и файлов нужному пользователю.

Одна миграция прошла не гладко: Windows загрузила временный профиль из-за старой записи ProfileList и разрешений на данные профиля. Исправил соответствие реестра и права файлов, подтвердил обычный вход. Сохранил последовательность восстановления для будущих миграций ПК.

Политики рабочих станций

Политики охватывают организацию домена, управляемые пароли локальных администраторов Windows LAPS, выдачу компьютерных сертификатов, проводной EAP-TLS и отдельные пользовательские параметры. Также изменил политику срока действия доменных паролей и проверил результат на обоих контроллерах.

Изменил GPO раскладок клавиатуры так, чтобы добавлять только отсутствующие раскладки без замены пользовательских методов ввода и порядка. Скрипты прошли отдельные проверки, но хочу проверить реальный переключатель на экране входа после следующего logon.

Удалённое администрирование

Настроил PowerShell remoting через WinRM с Kerberos и проверил несколько подключений между рабочими станциями и от рабочих станций к серверам. Это отдельно от RDP: на целевой системе по-прежнему нужны разрешения для конкретной задачи.

Централизованно развёртываемые инструменты

  • PowerShell 7: проверенный ZIP PowerShell 7.7 разворачивается через существующую GPO и задачу SYSTEM. Скрипт проверяет hash пакета, настраивает remoting и избегает повторной установки той же версии. Проверены шесть узлов Windows, но отдельные сценарии запуска после перезагрузки остаются открытыми.
  • Sysinternals и RSAT: централизованное распространение, RSAT только на выделенном административном компьютере.
  • Windows Admin Center: настройка HTTPS и диагностика сертификата/HTTP.sys, не только установка веб-консоли.
  • Sysmon: установка с управляемой конфигурацией и плановыми задачами; события полезны для расследований, полноценный SIEM ещё не создан.
  • RustDesk: собственный сервис поддержки с GPO, которая теперь выполняет проверяемые по версии обновления MSI и EXE до 1.5.3, с проверкой подписи и hash пакетов.

WireGuard подключается только вне дома

На ноутбуке Windows настроил автоматический запуск WireGuard вне домашней сети и отключение при возвращении. PowerShell-скрипт проверяет активные физические интерфейсы, запускается при старте Windows и событиях изменения сети. Задачи выполняются от SYSTEM, туннель может установиться до входа пользователя.

Проверил домашние Wi-Fi и Ethernet, переход на hotspot телефона, возвращение домой, перезагрузку вне дома и ручное управление через WireGuard. Скрипт запоминает текущее сетевое состояние, чтобы не отменять сразу ручное отключение. В журналах заметил перекрывающиеся события подключения, это нужно исследовать.

Проверка политик на обоих контроллерах

Проверил распространение изменения политики доменных учётных записей на оба Windows Server, не полагаясь только на значение в GPO editor. Конкретные параметры паролей не публикую; важно подтверждение согласованности результирующей доменной политики на обоих контроллерах.

Когда обновление RustDesk зависло

Одно MSI-обновление вернуло ошибку 1603. EXE обновил клиент, но скрипт ожидал дочерние процессы RustDesk и выглядел зависшим. Изменил ожидание на сам установщик с проверкой установленной версии. Следующий ручной запуск завершился без изменения сервера поддержки.

Отдельная групповая политика для Wi-Fi по сертификатам

У доменных Windows уже были компьютерные сертификаты и проводная политика 802.1X, но одна рабочая станция использовала старый локальный Wi-Fi-профиль с неверным режимом аутентификации. 25 ноября создал в Group Policy Management политику беспроводной компьютерной аутентификации с EAP-TLS, явным доверием CA и имени RADIUS-сервера и фильтром клиентских сертификатов по корпоративному CA и Client Authentication EKU.

Сначала применил её к пилотной рабочей станции. WLAN AutoConfig записал успешную компьютерную аутентификацию, подтвердил соединение через новый профиль. Расширил применение GPO на существующую разрешённую группу компьютеров, проверил репликацию и применение. Остальные выключенные клиенты на этом этапе отдельно не испытаны. Проводную политику, шаблон сертификата и RADIUS не менял.

Проблемы и дальнейшие работы

Некоторые задачи потребовали нескольких итераций. Способ установки PowerShell пришлось изменить, а HTTPS-listener Windows Admin Center проверить. Обновление RustDesk прошло на доступных тестовых ПК; один выключенный компьютер ещё требует проверки.

Также хочу проверить больше комбинаций источников и целей PowerShell remoting и убедиться, что установки через политики корректно работают после восстановления системы. Это практические последующие тесты, а не пробелы в описании развёртывания.
