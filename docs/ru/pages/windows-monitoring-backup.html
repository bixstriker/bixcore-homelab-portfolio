Мониторинг и резервное копирование Windows Server

После запуска Active Directory и служб сертификатов я хотел видеть проблемы до того, как они нарушат вход или сетевой доступ. Также нужен был план восстановления, выходящий за рамки второго контроллера домена.

Мониторинг сервисов

Установил Windows Exporter с коллекторами производительности системы, Active Directory, DNS, служб сертификатов, IIS и плановых задач. Prometheus собирает метрики, Grafana отображает наиболее часто проверяемые области.

Это даёт представление о нагрузке серверов, службах каталога, публикации сертификатов и выполнении плановых задач. Sysmon использую отдельно для исследования событий Windows; полноценный SIEM не строил.

Резервные копии System State

Настроил и проверил плановые System State backup контроллеров домена с использованием NAS. Заметки о восстановлении также охватывают DNS, сертификаты, разрешения и разумный порядок запуска сервисов.

Второй контроллер помогает при недоступности каталога, но не заменяет резервную копию базы CA и не гарантирует восстановление хранилища при отказе диска.

Когда резервное копирование сорвалось из-за сети

1 ноября еженедельная задача System State на одном контроллере завершилась ошибкой. Журналы Windows показали сброс Realtek NIC, затем ошибки SMB и прерванную запись на NAS. Я не считал красный индикатор ложным срабатыванием и не удалял последние рабочие бэкапы для улучшения графика.

Обновил драйверы Realtek обоих контроллеров Windows Server до нового серверного пакета. Оба адаптера восстановились, следующие еженедельные System State backup 8 ноября были отмечены успешными. Это обнадёживает, но нет новой независимой проверки каталогов копий или полноценного восстановления. Одна успешная неделя не доказывает невозможность повторения сброса NIC.

Нашёл слабость ротации бэкапов: она сортирует папки по датам, но пока не различает завершённые и частичные копии. Это нужно исправить, прежде чем считать сохраняемые копии последними тремя успешными бэкапами. Заметки об отказе и восстановлении →

Безопасное выключение контроллеров при работе от батареи

27 ноября добавил локальную плановую PowerShell-задачу на каждом контроллере. Каждая опрашивает свой ИБП через NUT, одна через NAS, другая через OPNsense. Задача работает как SYSTEM каждую минуту и запрашивает штатное выключение Windows только при двух измерениях с интервалом пять секунд, подтверждающих работу от батареи при заряде не выше 50 процентов.

Недоступность NUT-сервера, некорректное измерение, возврат сетевого питания или заряд выше порога предотвращают выключение. Решение принимается локально на сервере, поэтому удалённое администрирование не является зависимостью.

Проверил реальные показания online, имитацию порога без выключения серверов, ручные и плановые запуски от SYSTEM. Обе задачи завершились успешно. ИБП до порога не разряжал и фактического выключения от батареи не наблюдал. Порядок выключения тоже важен: NUT-сервер должен быть доступен до принятия решения зависимым контроллером.

Что ещё хочу проверить

Последние плановые задачи отмечены успешными, но ни один контроллер и CA не были заново восстановлены из полного проверенного комплекта копий. Хочу завершить это испытание, прежде чем считать план восстановления проверенным от начала до конца.
