Создание хоста Proxmox

Я хотел полноценную лабораторию firewall, но не хотел выделять ещё один мощный компьютер на постоянной основе. Решением стал старый настольный ПК с сохранённой Windows и загрузкой Proxmox по необходимости.

Windows и Proxmox на одном ПК

Установил Debian 13 и Proxmox VE 9.2 рядом с существующей Windows 11. Windows остаётся обычным вариантом загрузки; для лаборатории одноразовый UEFI BootNext запускает Proxmox. Проверил переключение без клавиатуры и монитора.

Позднее обновил CPU до Intel Core i7-4790K и подтвердил работу VT-d/IOMMU на хосте. Сетевую конфигурацию Linux перевёл с ориентированного на desktop NetworkManager на ifupdown2, лучше работающий с bridges Proxmox.

Сеть хоста и интеграция каталога

Сеть управления хоста и upstream виртуальных firewall имеют разные роли. У каждой firewall свой виртуальный LAN для тестовых Windows и Linux. Это позволяет переключать клиентов между системами без изменения повседневного домашнего шлюза.

Включил хост Proxmox в Active Directory через realmd и SSSD и установил доверенный HTTPS-сертификат управления внутреннего CA. IPv6 на management bridge потребовал дополнительной настройки обработки Router Advertisements в Linux при включённых forwarding и bridges.

Ранняя проблема VLAN/DHCP потребовала проверок физического коммутатора, тегированного uplink, bridge Proxmox и NIC гостя, а не только изменений виртуального маршрутизатора. Сохранил последовательность диагностики для последующих установок firewall.

Замена хранилища VM

Первый пул VM использовал два старых HDD без резервирования. После проверки SMART и ZFS решил перенести данные на другой диск вместо продолжения работы с проблемной конфигурацией.

Перенёс данные ZFS, обновил ссылки хранилища Proxmox, запустил существующих гостей и вывел старый пул из эксплуатации. Сейчас используется один диск ZFS на 2 TB. Для лаборатории по требованию это подходит, но при отказе диска понадобится восстановление из отдельного бэкапа.

Проверка хоста после ноябрьских обновлений

К 26 ноября хост работал на Debian 13.8 и Proxmox VE 9.3.1. После обновлений проверил загрузку, ZFS-пул и сервисы. Отказ AppArmor в пути перезапуска CUPS задерживал ротацию журналов; исправил профиль и проверил успешный CUPS и следующий logrotate. Изменение AppArmor нужно перепроверять после обновлений пакетов.

Проверил отдельный доступ SSH Ed25519 из Windows к учётной записи управления лабораторией. Root SSH по ключу не включал. Инвентарь 18 VM сохранён; snapshots не заменяют независимый бэкап однодискового пула.

Что хочу улучшить

Оставшиеся работы практические: восстановление вне хоста, дополнительные проверки перезагрузки и IPv6, полный тест путей, которые должны блокироваться. Обычно запускаю лишь две или три VM, поэтому надёжность и низкие расходы важнее постоянного кластера.
