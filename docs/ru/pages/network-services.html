DNS, DHCP и сетевые сервисы

Я хотел, чтобы у клиентов был надёжный DNS без необходимости направлять каждый интернет-запрос на контроллеры домена Windows. IPv6, гостевой доступ и обновление сертификатов добавили свои требования.

Как устроен DNS

OPNsense предоставляет DHCPv4 и локальную маршрутизацию. AdGuard — клиентский резолвер там, где нужна фильтрация, Unbound выполняет собственную DNS-роль и обслуживает отдельные внутренние записи. Запросы домена Active Directory пересылаются на DNS каталога.

IPv6-клиенты получают сведения о резолвере через Router Advertisements и RDNSS. Проверил нужное поведение DNS обычного и гостевого сегментов без привязки повсюду к одному семейству адресов.

Публичные записи и HTTPS-сертификаты

Динамический DNS обновляет внешние записи при изменениях WAN-адресации. ACME DNS-01 используется для продления сертификатов там, где нужно, а сертификаты reverse proxy NAS требуют отдельного обслуживания. Продление и внешнюю доступность сервисов проверяю независимо: успех одного не гарантирует другое.

Проверка AdGuard после обновления

Обновил AdGuard Home до более нового beta-образа с готовыми файлами отката, затем проверил DNS, доменную пересылку, блокировки, HTTPS, DoH и DoT. Открытый DoQ listener не считаю доказательством полноценного QUIC-подключения клиента. Выдача TLS-сертификатов на шлюзе автоматизирована; копирование в сервисы NAS пока ручное.

Гостевой доступ и сетевая загрузка

Гостевому Captive Portal нужна IPv6 AAAA-запись, следующая текущему префиксу гостевой сети. Добавил update hook и сравнил создаваемую DNS-запись с фактическим адресом. Механизм работал в документированном тесте; реальная смена префикса провайдера требует проверки.

Для сетевой загрузки использую PXE/ISO-сервис на NAS с ProxyDHCP в соответствующем клиентском сегменте, не заменяя обычный DHCP шлюза.

IPv6 Router Advertisements для обнаружения гостевого портала

URL Captive Portal API уже передавался через DHCPv4 Option 114. Я добавил RFC 8910 RA Option 37 в Guest VLAN и захватил реальные Router Advertisements. Guest содержал URL, Core и лаборатория IPv6-only — нет. RDNSS, сведения о префиксах и PREF64 сохранились. Это подтверждает отправку пакетов, но не реакцию каждой клиентской ОС.

Установленная версия OPNsense потребовала небольшой специфичный для версии патч генератора; файлы отката сохранены для будущих обновлений.

Когда вход сначала по IPv6 оставил IPv4 без доступа

У реального гостевого iPhone были IPv4 и IPv6, но после входа портал разрешил в таблице PF только IPv6. Выявил фильтр адресов Client Roaming OPNsense и применил upstream-исправление issue #11214. Существующая сессия получила IPv4 без нового входа, сохранила все девять IPv6-записей и прошла IPv6-readiness на 10/10. Исследование dual-stack портала →

Как дать IoT-камере обнаружить NAS, не открывая всю сеть

После переноса Xiaomi-камеры в изолированную IoT-сеть обнаружение NAS перестало работать. Камера отправляла NetBIOS discovery broadcasts, не проходившие границу VLAN. Использовал OPNsense UDP Broadcast Relay для обнаружения и узкое правило SMB от этой камеры к нужному интерфейсу NAS.

Проверил активные PF rules и захватил discovery- и SMB-трафик. При отключённом правиле камера не находила NAS, при включении обнаружение восстановилось. Затем подтвердил реальный импорт записей камеры на NAS. Общий запрет IoT → Core сохранён вместо доступа всех IoT-устройств к сети хранения.

Тест подтверждает эту камеру и её путь передачи, а не полную изоляцию от любого протокола. Изменять SMB-сервис NAS или учётные данные не понадобилось.

Отдельная проверка 22 ноября подтвердила AdGuard как резолвер обычных Core-клиентов, а Guest использует локальный резолвер шлюза для IPv4 и IPv6. Включённый listener зашифрованного DNS не доказывает его использование каждым клиентом.

Проблемы, с которыми я столкнулся

После перезагрузки динамический DNS перестал обновляться, хотя сервис работал. Причина — доступность upstream IPv6, а не отсутствие DNS-конфигурации. Это объясняют исследование DDNS и тесты исходных WAN-адресов и их связь с двумя симптомами.

Также задокументировал обновление IPv6-записей гостевого портала и исчезновение DNS-адреса NAS после сетевого события. Это отдельные проблемы с отдельными исправлениями.
